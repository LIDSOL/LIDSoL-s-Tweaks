** Lecciones aprendidas

- **prefs.js vacío → crash**: `fillPreferencesWindow()` debe agregar al menos un widget. Si no, GNOME falla con "Extension did not provide any UI".
- **Import ESM sensible a mayúsculas**: `import {ModuleLoader}` debe coincidir exactamente con `export class ModuleLoader`.
- **Keybinding keys**: Deben coincidir exactamente entre el schema y `Main.wm.addKeybinding()`. Error → crash del Shell (retorno a GDM).
- **`hook.js`**: Siempre verificar `typeof originalMethod === 'function'` antes de parchear prototipos.
- **`Gtk.Switch` en GTK4**: Usar `'active'`, NO `'state'` (propiedad eliminada de GTK3). `settings.bind(key, sw, 'active', ...)`.
- **`_loadSettings()` reconectar handlers**: Si se usa señal `changed::`, desconectar viejos y reconectar al recargar settings. Nunca confiar en que la señal anterior sigue viva tras recarga.
- **Quick Text dual-process**: Diálogo modal en St/Clutter (dentro del Shell), ventana Actions en Gtk/Adw (proceso separado vía `Util.spawn()`). El subproceso necesita shebang `#!/usr/bin/gjs -m`.
- **Background Clock**: NO monkey-patchear `BackgroundManager.prototype._createBackgroundActor`. Usar `Main.layoutManager._backgroundGroup.add_child()`.
- **JS getters vs GObject properties**: No definir `get canPlay() { }` en una clase `GObject.registerClass` que ya declara `'can-play'` como `GObject.ParamSpec.boolean(READWRITE)`. El getter JS shadowea la propiedad GObject y como no tiene setter, `this.canPlay = value` lanza `TypeError: setting getter-only property`. La señal `notify::can-play` nunca se emite, rompiendo cualquier código que dependa de ella. Siempre verificar que no haya conflicto entre `Properties:` del `registerClass` y getters/setters del prototipo.

*** Lecciones de Top Bar Organizer (1.4.1)

- **prefs.js no puede leer el estado vivo de la barra** (proceso GTK separado, sin `Main.panel`). Para que el dialog "solo muestre lo que existe", el trabajo se delega al módulo del shell vía **D-Bus**: prefs expone el botón "actualizar", llama a `org.gnome.Shell.Extensions.LidSolWidgets.CleanTopBar` (método exportado por `TopBarOrganizerModule`), el módulo reconstruye los `tbo-*-box-order`/`tbo-hide`/`tbo-show` y el dialog se reconstruye en el callback.
- **D-Bus IMPORTANTE — exportar el objeto en la MISMA conexión que posee el nombre**: si usas `Gio.bus_own_name(...)` (crea una conexión PRIVADA interna) y exportas con `Gio.DBus.session.export_object(...)` (conexión COMPARTIDA), son conexiones DISTINTAS → el nombre resuelve a una y el objeto está exportado en la otra → las llamadas fallan (`"No se pudo actualizar la barra"` aunque el módulo esté activo; el botón de "Actualizar barra" falló hasta fix 2026-08). Solución correcta: exportar dentro del **`bus_acquired_handler`** de `bus_own_name`, usando la conexión que recibe ese callback (`connection.export_object(path, iface, methodHandler)`), y guardar `this._dbusConnection = connection` para hacer `unexport_object` en `disable()`.
- **`Main.panel.statusArea[role]` persiste tras deshabilitar un módulo**: p.ej. `disable()` de batteryIndicator destruye el container pero NO borra `statusArea['lidsol-battery-indicator']`. Por eso comprobar solo `statusArea[role]?.container instanceof St.Bin` NO basta → hay que verificar que el container sea hijo vivo de `_leftBox/_centerBox/_rightBox` (como hace `_cleanTopBar()`).
- **`saveNewTopBarItems` solo añade, nunca borra** → los roles obsoletos quedan guardados. `_cleanTopBar()` reconstruye los órdenes directamente desde los containers vivos de cada box (con reverse en el box derecho, RTL) y filtra `hide/show`; escribe con comparación `JSON.stringify` para evitar loops de señal.
- **Comunicación prefs → shell**: en este proyecto la limpieza es **manual** (botón) y no automática; se usó D-Bus para tener un call-and-response determinista (prefs espera la llamada para `_rebuildAll()`), evitando claves GSettings `tbo-clean` con patrón de sentinela frágil.
- **CRÍTICO — un throw en `enable()` mata TODO el módulo**: `ModuleLoader._enableModule` envuelve `moduleInstance.enable()` en `try/catch` (moduleLoader.js); si `enable()` lanza (p.ej. el setup D-Bus `Gio.bus_own_name`/`Gio.DBus.session.export_object` falla), NO se registra el módulo y **nunca** se enganchan el patch de `Panel._addToPanelBox` ni las conexiones `changed::` → la barra no reordena ni oculta (regresión 2026-08). Lección: el bloque D-Bus debe ir **DESPUÉS** del wiring esencial (patch + conexiones + `_handleNewItemsAndOrderTopBar()`) y envuelto en `try/catch` para que un fallo de D-Bus NUNCA deshabilite la barra.
- **El role de `statusArea` NO debe ser el nombre visible de la extensión**: el Workspace Indicator usaba `extension.metadata.name` ("LIDSoL's Tweaks") como role → en el dialog TBO se mostraba un item "LIDSoL's Tweaks" y roles duplicados obsoletos quedaban guardados en los `tbo-*-box-order`. Fix: usar un role estable y único (`'lidsol-workspace-indicator'`) y mapear a nombre amigable en `TOP_BAR_ITEM_NAMES`/`TOP_BAR_ITEM_ICONS` de prefs.js. Además `_saveNewTopBarItems` ahora deduplica (`[...new Set(...)]`) cada box-order antes de guardar.
- **Roles obsoletos**: roles muertos acaban guardados en los `tbo-*` (aquí `"LIDSoL's Tweaks"` y `'workspaceBar'`). `_removeObsoleteRoles()` los filtra de todos los `tbo-*` keys de forma automática (no hace falta el botón de actualizar). El role nuevo del workspace indicator debe quedar también en `DEFAULT_BOX_BY_ROLE = { 'lidsol-workspace-indicator': 'left' }` para que se coloque en la caja izquierda por defecto (si no, `addToStatusArea` sin box lo pondría en la derecha y `addNewItems` lo guardaría ahí).
- **El ícono del dialog debe existir en el sistema**: `desktop-symbolic` NO existe → ícono en blanco. Usar uno real (`preferences-desktop-multitasking-symbolic`). `_saveNewTopBarItems` también escribía `default-left/center/right` que NO existen en el schema (throw si `isFirstTime`); se eliminaron esas escrituras muertas.

*** Lecciones de Overlay Mode (Quick Settings)

- **2.4.1 (nativo + acordeón + fade)**: se eliminó el enfoque de constraints/flyout/dialog y el
  "reparto" del hueco (v2, rama banda-esencial preserva el enfoque con lag). La animación nativa
  (easing de altura + fade + dim) se conserva intacta y solo se parchea `QuickSettingsLayout`.
  Mientras el menú del toggle crece, TODAS las filas salvo la pulsada se desvanecen y colapsan su
  altura hacia 0 con el mismo ease del menú (`POPUP_ANIMATION_TIME/2`, easeOutCubic), sincronizados
  por una "sesión" por apertura. Con el progreso p: filas no activas = `altura*(1-p)` y
  `opacidad 255*(1-p)` (más `clip_to_allocation` en esa sesión); la fila activa queda natural y el
  toggle sube suavemente con el acordeón; el contenedor termina envolviendo solo "fila del toggle +
  menú" (nada se desborda, sin banda vacía). Al cerrar, en espejo (1→0).
  `QuickSettingsLayout` es una clase JS registrada **no exportada**: se obtiene con
  `grid.layout_manager.constructor` y se subclasea (`GObject.registerClass(class X extends ...)`)
  sobreescribiendo `vfunc_allocate` y `vfunc_get_preferred_height` (sin sesión ambos delegan en el
  nativo vía `super` → modo cerrado idéntico). Al sustituir `grid.layout_manager` se recrean los
  child metas (column-span vuelve a 1): **capturar los spans antes** y reaplicarlos tras el
  reemplazo y al restaurar en `disable()`.
- **Números clave del grid en el shell (quickSettings.js)**: el grid tiene como primer hijo un
  "placeholder" (`Clutter.Actor` con `BindConstraint HEIGHT → _overlay`), cuya altura es la altura
  ACTUAL del menú (el overlay es un `Clutter.Actor` con `BinLayout` cuya preferred sigue la altura
  forzada del actor del menú durante su ease) — es lo que re-layoutiza el grid y anima el hueco
  nativo. `_getRows()` incluye ese placeholder en sus filas: durante una sesión se **excluye** de
  las filas y se descartan las filas vacías resultantes (la fila espaciadora es justo lo que se
  está plegando). El cierre nativo fades el contenido del menú y LUEGO baja la altura del actor
  antes de ocultarlo: la sesión detecta el cierre cuando la altura del overlay empieza a decrecer
  (o cuando el menú ya no es visible).
- **Sincronía**: el progreso de la sesión se anima con un `GLib.timeout` (60 Hz, solo mientras hay
  sesión) con `easeOutCubic` y duración `POPUP_ANIMATION_TIME/2` (import del namespace
  `quickSettings.js` con fallback 400 — un named import lanzaría si el export cambiara de nombre).
  Así el colapso comparte duración y curva con el ease de altura del menú. `super.vfunc_get_preferred_height`
  existe en 50.5 y main (verificado) → modo cerrado nativo sin reimplementar.
- **GNOME 51**: `QuickToggleMenu.open(params)` delega en `PopupMenuBase.open`, que emite
  `open-state-changed` ANTES de montar la animación nativa (en 50.5 se emitía después). Cualquier
  código que cancele/reemplace la animación nativa desde esa señal (el overlay antiguo) pierde la
  animación. El reparto no escucha la señal: detecta la fila activa por `menu.actor.visible` en el
  propio `vfunc_allocate` (idéntico en 50.5 y main).
- El overlay (`QuickSettingsMenu._overlay`) necesita coordenadas stage-absolutas. Vincular constraints a `menu.box` da coordenadas relativas al padre → overlay aparece en x=0.
- Usar `menu._boxPointer` como source de `Clutter.BindConstraint` para ambos ejes (X e Y).
- `_xconstraint.offset` debe actualizarse en `_onOpen()` y en el handler `notify::height`, igual que `_yconstraint.offset`.
- Al fijar `menu.actor.width`, también setear `x_align = Clutter.ActorAlign.CENTER` para que el menú se centre dentro del overlay.
- Para animaciones con overshoot (flyout/dialog), usar `AdvAni.ease()` con `AdvAnimationMode.LowBackover` / `MiddleBackover` en vez de `Clutter.AnimationMode.EASE_OUT_BACK` / `EASE_OUT_EXPO`. Los custom bezier curves dan un efecto más natural.
- **Siempre conectar handlers GSettings ANTES del early return de `enabled`**, si no, al deshabilitar/re-habilitar el módulo nunca se vuelven a conectar las señales y el toggle queda muerto.
- Separar claves GSettings en dos grupos: las que requieren `disable()+enable()` (reload) y las que solo necesitan `_loadSettings()` (live: duration, style, overflow anchor).
- `_scheduleReload()` debe capturar `this._gsettings` en variable local antes de llamar a `disable()`, porque `disable()` lo setea a `null`. Sino `enable(this._gsettings)` recibe `null` y crashea.
- **GObject.registerClass NO admite re-registrar una clase con el mismo nombre en el proceso**: GJS lanza `Type name 'Gjs_<Nombre>' is already registered` aunque la expresión de clase sea nueva (verificado con `gjs -m`; nombres distintos OK). `_applyAccordionLayout()` lo hacía en cada `enable()` → al desactivar el módulo (o alternar overlay OFF→ON vía `_scheduleReload`) y re-activar, el throw escapaba de `QuickSettingsTweaksModule.enable()` (sin try/catch) hasta `ModuleLoader._enableModule`, que lo captura y NO registra el módulo → imposible recargarlo hasta reiniciar la shell. Fix: cachear la subclase registrada en un `WeakMap` por constructor del layout nativo (`_accordionLayoutCache`) — registrar UNA vez, reutilizar en re-enables. Además `disable()` debe cerrar la sesión viva del layout (`_lidsolEndSession()`) para no dejar `clip_to_allocation`/opacidad alterados ni el timeout de la sesión corriendo.
- **2.4.1.2 (leyenda "N Background Apps" fuera del contenedor / sin fondo tras el regreso)**: la leyenda es un quick-toggle dinámico (`BackgroundAppsToggle`, `visible = !isLocked && (menu.isOpen || nBackgroundApps > 0)`, proxy DBus `org.freedesktop.background.Monitor` ASYNC) añadido al FINAL del grid con `column-span = N_QUICK_SETTINGS_COLUMNS` (fila de ancho completo; su fondo es `transparent` por tema → "sin fondo" = está FUERA de la tarjeta del popup). La sesión del acordeón CONGELABA `rows` al abrir → si la leyenda aparecía en mitad de sesión (nApps 0→1 con el proxy sin resolver aún, o app que arranca con un submenú abierto) quedaba perdida: `preferred` con filas congeladas (corto) vs `allocate` nativo live (alto) → overflow → leyenda debajo del contenedor y, sin relayout posterior, el estado roto persistía. Fix: **membresía LIVE en `vfunc_get_preferred_height` y `vfunc_allocate`** (`_getRows` + strip del placeholder cada frame, `_lidsolStripPlaceholder`); se congela solo lo imprescindible por IDENTIDAD de hijo: `heights` WeakMap hijo→[minH,natH] (una medida por hijo/sesión — sin preferred por frame), `activeChild` (hijo con `menu.actor` visible; reinicio de sesión por identidad en vez de por índice) y `clipped` (Set). Hijos que aparecen a mitad (la leyenda) se cachean en su primer frame y se pliegan como el resto; preferred==allocate por construcción → el contenedor SIEMPRE envuelve la leyenda visible y nunca se queda corto. Además `_lidsolEndSession()` fuerza `container.queue_relayout()` para que el dimensionado nativo se aplique siempre al terminar la sesión.

*** Lecciones de Transition Animations (Workspace Indicator)

- `ws-transition-animation` schema key: enum `none`/`slide`/`slide-bounce`/`fade`/`glow`, ubicado en el schema tras `ws-custom-styles`.
- **Estrategia**: `_updateWorkspacesBar()` distingue cambio estructural (add/remove/reorder → `_fullRefresh()`) de cambio de activo (→ `_updateInPlace()`).
- `_updateInPlace()` en modo slide: las labels wsBox reciben clase `inactive` (sin `active`), y un `St.Bin` (`_activeIndicator`) con `fixed_position_set=true` se mueve entre wsBoxes animando `{x, y, width, height}` vía `ease()`. En modos no-slide usa active/inactive normal en labels.
- `_activeIndicator` se crea en `_initWorkspacesBar()` y se recrea en `_fullRefresh()` (destroy_all_children lo destruye). Posicionamiento inicial via `GLib.idle_add` para esperar layout.
- **`_fullRefresh()`** se llama si `existingCount !== expectedCount` o `existingCount === 0` (primera carga). Recrea indicator + wsBoxes y agenda `_syncIndicator()` en idle.
- **`_syncSlideIndicator()`** oculta/muestra el indicator según modo.
- **Animaciones:**
  - `slide`: indicator ease `{x, y, width, height}` con `EASE_OUT_QUAD`, 250ms.
  - `slide-bounce`: mismo con `EASE_OUT_BACK`, 300ms (overshoot suave).
  - `fade`: label nuevo activo `opacity 0 → 255` con `EASE_OUT_QUAD`, 250ms.
  - `glow`: wsBox `scale 1.0 → 1.12 → 1.0` con `EASE_OUT_QUAD`, 150+200ms.
- `_prevActiveIndex` guardado en constructor, actualizado al final de `_updateWorkspacesBar()`.

*** Lecciones de Album Art (capas CSS)

**Modelo:** `extension/utils/mediaPlayer/albumArt.js` es el único propietario del art. Renderiza capas `St.Widget` con `background-image` (`background-size: cover` + `border-radius`) y nunca decodifica: la carga asíncrona la hace el propio St. Un resolver a nivel de módulo, compartido por todas las instancias, normaliza cualquier carátula a un `file://` local en `~/.cache/lidsol-widgets/album-art`:
- `http(s)`: descarga async con una `Soup.Session` compartida, dedup in-flight (dos widgets con la misma URL comparten una petición) y escritura atómica tmp → `GLib.rename`, para que un stream truncado nunca llegue al cache.
- `file://`: copia con clave `MD5(url|mtime)`, lo que detecta que el reproductor reescriba el mismo archivo entre pistas. Además reintentos de 500ms ×10 para archivos que aún no existen o están vacíos, y `Gio.FileMonitor` con debounce de 200ms (registrado también para archivos que YA existen, para que una reescritura vuelva a copiar).
- `data:`/otros: passthrough directo al CSS.
- LRU de 50 entradas con cleanup diferido de 5s.

**Estado de resolución explícito** (4 variables, no una): `_currentUrl` = fuente pedida, `_loadedSource` = fuente cuyo art está en pantalla, `_pendingUrl` = fuente en vuelo, `_watchedUrl` = fuente vigilada por esta instancia. Más `_requestSeq` para secuenciar: una descarga lenta que llega tarde descarta su resultado si una petición más nueva reclamó antes (`seq !== this._requestSeq`).

**Causa raíz de la carátula negra tras desbloquear (solo en el at-a-glance):** St cachea la textura del `background-image` dentro del `StThemeNode` (`node->background_texture`) y solo la invalida por cambio de archivo (`StTextureCache::texture-file-changed`) o de allocation, **nunca por un reset del compositor**. En el ciclo bloquear/desbloquear ese puntero queda muerto y la capa se pinta negra. Afecta únicamente al at-a-glance porque es el único widget que vive en el panel, el actor que GNOME no destruye al bloquear; dashboard y dateMenuMedia están en popups/overview que se recrean al volver, con theme node nuevo, y por eso funcionaban.

**Fix:** `setArt(url, true)` → `_showLayer(uri, force)`. Con `force` se crea una capa nueva aunque la URI sea idéntica (theme node nuevo → St recarga la textura del cache), con el fade de cambio de pista. Ojo: el handler de `screen-unlocked` **ya llamaba** `setArt(url, true)` y era un no-op, porque `force` solo saltaba la idempotencia de `setArt()` mientras `_showLayer()` hacía early-return con la misma URI. El flag tenía que propagarse hasta el final de la cadena, no solo hasta `setArt()`.

**Alternativa descartada:** `St.ThemeNode.invalidate_background_image()` existe y es accesible desde JS (verificado en `/usr/lib/gnome-shell/St-51.typelib`: `peek_theme_node`, `get_theme_node`, `invalidate_background_image`). Recrear la capa es el equivalente vía API pública y está respaldado por la evidencia de que las superficies con actor recreado funcionan así.

**Reglas del crossfade por capas:**
- Un fade solo limpia si su capa sigue siendo la vigente (la última añadida). Si dos fades se solapan y ambos limpiaran, se destruirían mutuamente y podría no quedar **ninguna** capa (carátula negra).
- Un fade interrumpido (bloqueo de pantalla, destrucción) nunca debe dejar la capa a media opacidad: si sigue viva, se restaura a 255 en `onStopped` aunque `!isFinished`.
- Ante fallo definitivo se limpia a vacío: la carátula de la pista anterior solo se conserva mientras la nueva está resolviéndose, nunca como estado final.

**Trampas de la API verificadas en gjs 1.90 / Shell 51:**
- `Soup.Session.send_and_read_async` exige **4** argumentos: el callback va explícito y el resultado se obtiene con `send_and_read_finish(res)`.
- No existe `Gio.FileMoveFlags` ni `move()` de 3 argumentos: usar `GLib.rename`, que además es la syscall directa (atómica).
- `Gio.File.copy_async` exige **6** argumentos, con `progress_callback` en 5ª posición.
- `GLib.Bytes` → `Uint8Array` con `bytes.get_data()` (o `toArray()`).

**Bugs cazados por el harness al escribir el fix:**
- `options.roundness` se ignoraba en el constructor (el dashboard lo pasa; el radio solo se aplicaba luego, por el setter).
- Los dos fades concurrentes que se destruían mutuamente.

**Lección del harness:** cargar el **fuente real** del módulo sustituyendo solo los `import 'gi://...'` por mocks (reloj virtual + fs real), y recargar el módulo entre tests para aislar el estado a nivel de módulo (`_sources`, `_inflight`, `_cleanupId`). **No usar réplicas manuales del módulo**: la réplica anterior divergió del código real y por eso no cazó el bug de `Gio.FileMoveFlags`; el harness actual sí cazó los tres bugs de arriba. Verificar cada fix revirtiéndolo y comprobando que el harness falla.

**Caja del art: la altura no la decide el layout, y por eso no se arregla con CSS** (fix `7772577`):

- En un `St.BoxLayout` **horizontal**, `clutter_box_layout_allocate()` asigna a cada hijo el eje cruzado completo del contenedor (`child_allocation.y1/y2 = box->y1/y2`) y `allocate_box_child()` solo llama a `clutter_actor_allocate()` sin reajustar nada: la **anchura** la decide el layout, la **altura** no.
- Después, `clutter_actor_adjust_height()` → `adjust_for_alignment()` interpreta el `y_align` contra esa caja: `FILL` (el valor por defecto) hace *"do nothing"*, así que el actor se queda con la altura completa; `CENTER/START/END` la recortan a su altura **natural** y lo centran. El art no tenía `y_align` → quedaba en `22 × altura del contenedor`.
- Esa altura la fija el hermano más alto del contenedor. `set_width()`/`set_height()` no fijan nada (`clutter_actor_set_width_internal()` solo hace `set_min_*` + `set_natural_*`) y `st_widget_allocate()` hace `clutter_actor_set_allocation()` **sin recortar a `max-height`**, así que con la etiqueta del reloj por encima de 22px el art acababa más alto que ancho.
- Consecuencia visual: el `border-radius: 11px` deja de ser un círculo y `background-size: cover` recorta los lados → óvalo vertical con el contenido achatado.
- Reglas derivadas: (1) cualquier contenedor del art le da `x_align`/`y_align: CENTER` (patrón que ya usaba el dashboard); (2) las reglas `min/max-*` de `.at-a-glance-media-art` son **CSS muerto**, porque `AlbumArt.vfunc_get_preferred_width/height` devuelve `[_size, _size]` **sin encadenar** a `StWidget` y el ajuste del theme node nunca se ejecuta; (3) el `border-radius` de la clase lo pisa el `set_style()` inline con el mismo valor.
- Descartado con datos antes de tocar nada: escalado HiDPI o fraccionario (monitores a `scale 1`, `scaling-factor 0`, `text-scaling-factor 1.0`); que St deformase la imagen (`get_background_scale()` en `st-theme-node-drawing.c` usa `MAX(area/img)` con escala uniforme para `cover`, es decir, recorta y no estira); márgenes (ninguno en esa clase); `stylesheet.css` (solo reglas `.wsb-*`).

*** Lección: St ignora la propiedad CSS `opacity` (fix `4.4.1.1`)

- La propiedad CSS `opacity` **no produce transparencia en el render de St** (`StThemeNode`): se parsea pero no hay canal `opacity` en el pipeline de pintado. Por eso eran no-ops tanto `.at-a-glance-indicator:hover/:active { opacity: 0.6/0.7 }` como la familia `opacity` de `dateMenuMedia.css` (`.dmm-header`, `.dmm-artist`, `.dmm-time, .dmm-duration`). Para atenuar hay que usar colores con alfa (`rgba(255,255,255,0.17)`) o `background-color` translúcido + `border-radius` + `transition-duration` para el fundido. Pendiente anotado en `4.4.3.2`.
- **Feedback de caja vs feedback de hijo:** el fill nativo de `clock-display` se pinta solo en el hijo `.clock` (mixin `panel_button($highlighted_child: true)`, `_panel.scss`), así que envuelve solo la hora y dejaba la media fuera. Para cubrir todo el bloque at-a-glance (hora + art + visualizador + etiqueta): neutralizar el fill del hijo (`box-shadow: none !important`) y aplicar el fill al contenedor completo, gobernado por los **estados nativos del botón** (`.clock-display:hover` / `:active`, que St gestiona solo vía `track_hover` y el `open-state` del menú) — alphas nativos `panel_button_fill` (`transparentize($fg, .83/.72/.68)` → 0.17/0.28/0.32), radio `999px`, `transition-duration: 150ms`, padding `12px` L/R (el padding nativo de `.clock`) como espacio de envuelta.
- **Pseudo-clases añadidas a mano en JS** (`.connect('enter-event')` → `add_style_pseudo_class('hover')`, etc.) **nunca produjeron feedback visible** en el contenedor, mientras que los estados nativos del botón siempre funcionaron; la lección es gobernar estos fills desde los estados nativos y no reinstrumentar el hover en JS.

*** Lección: un widget sin sync inicial nace en su estado por defecto y reserva espacio (fix `4.4.1.2`)

- `AtAGlanceIndicator.enable()` solo sincronizaba la visibilidad de los widgets multimedia (`_updateMediaVisibility()`) cuando `getActivePlayer()` devolvía un reproductor. En un login sin reproductores esa ruta nunca corría y la carátula conservaba su estado por defecto (`visible: true`): 22×22 px vacíos y transparentes a un lado de la hora, hasta que la primera señal de reproducción real (play → pausa → debounce) ejecutaba por fin el sync y la ocultaba. Por eso "el relleno se normaliza tras reproducir y pausar".
- Los contenedores (`ClutterBoxLayout`) **saltan en preferred-size y allocate a los hijos invisibles** (`if (!clutter_actor_is_visible(child)) continue`), así que un widget `visible: false` **no** reserva espacio: el "espacio anómalo" no era de layout sino una carátula que seguía visible sin tener nada que mostrar.
- Regla derivada: un widget cuya visibilidad depende de un evento debe (1) nacer oculto (`visible: false` en el constructor) y (2) sincronizarse SIEMPRE en `enable()`, incluido el caso "no hay datos" (espejo del else del handler `player-changed`), no solo cuando hay un reproductor activo.

*** Lección: fades del at-a-glance y familia `opacity` de dateMenuMedia (fix `4.4.3.2`)

- **`ease()` interrumpido sí invoca `onStopped` con `isFinished=false`** (mismo patrón que las capas de albumArt): un fade muerto por un evento más nuevo (skip rápido, `media-changed` que cae en pleno crossfade) ejecuta igual su callback. El `_crossfadeMedia` original ignoraba `isFinished` y aplicaba el swap de texto aunque el fade estuviera anulado → dos fades peleando, texto/opacidad equivocadas ("a veces el fade no se muestra").
- **Época de presentación (`_fadeSeq`)**: todas las transiciones del at-a-glance resuelven en un presentador único (`_updateMediaVisibility(opts)`); cada llamada pulsa un contador monótono y cada `onStopped` captura su `seq`, descartándose si ya hay una presentación más nueva → "latest wins", sin callbacks stale.
- **Metadata vacía transitoria** (GSConnect al adelantar/next desde el teléfono): el reproductor puede emitir brevemente `title=""`/`cover=""` sin haber cambiado de pista. Si se procesa, el label hace crossfade a vacío y queda un hueco negro. Regla: nunca sustituir contenido real por metadata vacía (guard en `_onMediaUpdate`, debounce de pausa y `_syncPlayerState`).
- **Restaurar a opacidad completa**: una presentación cuyo destino es "misma visibilidad + mismo texto" no debe ser no-op: si el actor quedó a media opacidad por un fade interrumpido (label, reloj, art, visualizer) se re-funde a 255.
- **Gate `mapped`**: los fades solo corren si `_container.mapped` → login/arranque sin animación; `screen-unlocked` pasa `{instant:true}` (recuperación forzada de la textura, sin coreografía).
- **El dimming del header de dateMenuMedia ya vivía en JS**: `actor.opacity = 153` (0.6) en `.dmm-app-icon` y `.dmm-player-name`; la regla CSS `.dmm-header { opacity }` era redundante y se eliminó. Artista y tiempos se atenúan con `color: rgba(255,255,255,0.8/0.7)`, no con `opacity` (St la ignora).

Esta sección se reescribió: la versión anterior afirmaba que el `background-image` de CSS no funciona en ningún actor tras un lock/unlock, y describía cambios en `crossfadeArt.js`. **Recorrido de intentos:**

1. `1ea7641` — `Clutter.Canvas` como `content` del widget, dibujando el pixbuf con Cairo y clip circular (`cr.arc` + `cr.clip()` + `Gdk.cairo_set_source_pixbuf()` + `cr.paint()`). 2. `f3a4a4f` — se vuelve a `St.DrawingArea` + Cairo por el mismo bug.
3. Estado actual — vuelta a capas CSS, pero **forzando la recreation de la capa** en el desbloqueo.

*** MPRIS stack (custom, NOT using MessageList._mediaSource)

**Source class** (GObject.Object):
- Creates a `Gio.DBusProxy` for `org.freedesktop.DBus` on the session bus
- On ready: calls `ListNamesAsync()` → filters names starting with `org.mpris.MediaPlayer2.`
- Connects `NameOwnerChanged` signal on the D-Bus daemon for dynamic add/remove of players
- Maintains `Map<string, Player>` of active players
- Signals: `player-added(busName, player)`, `player-removed(busName)`

**Player class** (GObject.Object):
- Constructor takes `busName`, creates 3 parallel D-Bus proxies:
  1. `_propertiesProxy` → `org.freedesktop.DBus.Properties` (for async `GetPosition`)
  2. `_playerProxy` → `org.mpris.MediaPlayer2.Player` (PlayPause, Next, Previous, SetPosition, Metadata, PlaybackStatus, CanGoNext, CanGoPrev, CanPlay, CanSeek)
  3. `_mprisProxy` → `org.mpris.MediaPlayer2` (Raise, DesktopEntry, Identity, name-owner tracking)
- Metadata parsing (`_parseMetadata`):
  - `mpris:trackid` → `_trackId`
  - `mpris:length` → `_length` (microseconds)
  - `xesam:artist` → `_trackArtists` (array, fallback "Unknown artist")
  - `xesam:title` → `_trackTitle` (fallback "Unknown title")
  - `mpris:artUrl` → `_trackCoverUrl`
- Controls: `previous()`, `next()`, `playPause()`, `raise()` — all via async D-Bus
- Position: async getter (GetAsync → int64), setter (SetPositionAsync with trackId)
- GObject properties: `can-play` (boolean), `can-seek` (boolean)
- Signal: `changed` on any metadata/status change
- Tracks `NameOwnerChanged` on its own proxy → emits `closed` when player disappears

*** MprisPlayer (shared/media.js lines 53-214)

- Creates 2 D-Bus proxies per player:
  - `MprisProxy` → `org.mpris.MediaPlayer2` (Identity, DesktopEntry, CanRaise, Raise)
  - `MprisPlayerProxy` → `org.mpris.MediaPlayer2.Player` (PlayPause, Next, Previous, Metadata, PlaybackStatus, CanGoNext/Prev/Play/Pause, Shuffle, LoopStatus, Volume, Position, SetPosition)
- Getters: `busName`, `trackArtists[]`, `trackTitle`, `trackCoverUrl`, `playBackStatus`, `canGoNext`, `canGoPrev`, `canPlay`, `shuffleStatus`, `loopStatus`, `volume`, `entry`, `identity`
- Actions: `playPause()`, `next()`, `previous()`, `shuffle()`, `loop()`, `setVolume(v)`, `raise()`
- Smart close: monitors `notify::g-name-owner` → emits `closed` when player vanishes
- Signal: `changed` on any property update

_sync() method:
- Updates title/artist text
- **Cover art**: copies URI to `~/.cache/aylur/media/{artist}_{title}` via `Gio.File.copy_async()`, then sets CSS `background-image: url("file://...")`. Uses sanitized filename. Falls back to bundled `missing-cover-symbolic.svg`.
- Play/pause icon based on playback status
- Shows/hides shuffle/loop based on status availability
- Loop: cycles icons (repeat → repeat-song), uses `insensitive` pseudo-class for inactive
- Volume slider: hidden if blacklisted player or volume=-1. Volume icon changes by level. Only sets value when not being dragged.

*** Media (shared/media.js lines 448-517) — D-Bus scanner

- Creates DBusProxy to `org.freedesktop.DBus`
- `ListNamesRemote()` → filters `org.mpris.MediaPlayer2.*`
- Maintains `Map<busName, MprisPlayer>`
- `getPreferred()`: returns player whose busName includes `this.preferred` string, falls back to first player
- `getPlayers()`: returns all MprisPlayer instances as array
- Listens to NameOwnerChanged for dynamic add/remove

** Implementation strategy for step 1.5 (date menu media widget)

The widget should be injected into the date menu's **right column** (above the calendar grid) using the same pattern as userAvatarDateMenu:

1. **Module location**: `extension/modules/dateMenuMedia/` (separate from dateMenu module)
2. **Injection**: navigate to `_menuBox.get_last_child()` (right column), insert at index 0
3. **MPRIS data**: use existing `MediaPlayerManager` singleton from `utils/mediaPlayer/mediaManager.js`
4. **Cover art**: use `AlbumArt` from `utils/mediaPlayer/albumArt.js`: capas CSS, y `setArt(url, true)` tras un unlock para forzar una capa nueva
5. **Widget structure**:
   - Base container: `St.BoxLayout` (vertical)
   - Album art area (if enabled)
   - Title + artist labels
   - Control buttons: prev, play/pause, next
   - Progress bar (optional, from QST)
6. **Settings prefix**: `dmm-` (Date Menu Media) to avoid conflict with dateMenu's `dm-*`
7. **Key settings for phase 1** (minimal):
   - `dmm-enabled` (bool) — master toggle
   - `dmm-show-prev`, `dmm-show-pause`, `dmm-show-next` (bools)
   - `dmm-control-opacity` (int, 0-255)
   - `dmm-compact` (bool)
   - `dmm-progress-enabled` (bool)
   - `dmm-progress-style` (string: 'slim'/'default')
8. **Layout styles from 1.6** (later):
   - `dmm-style` (int: 0=normal, 1=label-on-cover, 2=full)
   - `dmm-cover-width`, `dmm-cover-height`, `dmm-cover-roundness` (ints)
   - `dmm-text-align` (int: 0=left, 1=center, 2=right)
   - `dmm-text-position` (int: 0=top, 1=bottom)
   - `dmm-show-volume` (bool)
   - `dmm-show-loop-shuffle` (bool)
   - `dmm-fade` (bool)
